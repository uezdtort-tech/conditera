## 2. Решения владельца — исполнение

1. **Anti-fraud лимит — ИСПОЛНЕНО (revert, `c408a20`)**: регистрация возвращена
   к исходным **3 попытки/час, 10/день** (значения origin/main). Повышение
   3→10 считается НЕ одобренным до подтверждения владельцем необходимости и
   защиты от злоупотреблений. ЕДИНСТВЕННОЕ численное смягчение в candidate-
   диапазоне устранено — теперь candidate строже или равен origin/main по всем
   лимитам.
   **E2E-совместимость без ослабления лимитера**: арифметика регистраций на
   прогон — 4 попытки (auth-flow 2 негативные + integration-auth-flow 1 реальная
   + onboarding 1 реальная [только full-stack]) при лимите 3/час на общий
   0.0.0.0-бакет → 4-я попытка падала бы. Спекам выделены per-spec
   симулированные `x-real-ip` (10.20.0.21/22/23): канал доверенный по дизайну
   `extractIp` (в production перезаписывается Caddy; прямой доступ к :3000
   извне запрещён — инвариант docs/DNS_SETUP.md), **производственный лимитер
   не ослаблен**, сами лимиты в E2E выполняются реально (каждая спека ≤3
   попыток на свой IP). Ассерты не ослаблялись (негативные тесты сохранили
   толерантность [400,422,429]; реальные — точные 201/ok).
2. **Production auth — OWNER DECISION** (§1.C).
3. **Объём первого релиза — владелец**; P1-матрица §4 даёт фактическую базу:
   пилот включают только сценарии с реальной приёмкой.

**Webhook-регрессии — добавлены (`8f9d970`, тесты only, route.ts не тронут)**:
секрет → 401 (БД не затрагивается); non-UUID orderId → 404 а не 500;
отсутствие провайдера → без сверки и без 500; недоступный провайдер → 500
fail-closed; мусорное тело → 400.

**НАЙДЕННЫЙ ФАКТ (документируется, НЕ исправляется)**: PAY-1a skip-ветка
`provider_not_configured` (`route.ts:126-131`, введена `49604e0`) —
**недостижимый мёртвый код**: безусловный guard `:83`
`if (!isYookassaConfigured()) return { ok: true }` перехватывает случай раньше
(без маркера skip). Поведение корректно (без верификации, без 500, секрет
проверяется) — дефекта нет; чистка мёртвой ветки — только по отдельному
согласованию владельца (правило «платёжный код без согласования не изменяется»).
Денежные расчёты/escrow/балансы/выплаты/возвраты: **0 изменений** (v4.4 §3).
