# KNOWN LIMITATIONS — что осталось незавершённым

> Честный список на момент релиза release/readiness-fixes. Обновлять по мере закрытия.

## Финансы / платежи

1. **Ledger-журнал баланса (0038) не влит.** Ветка `pay2-wip` содержит
   additive-миграцию 0038 (журнал всех движений баланса + оверлоады RPC).
   Она совместима с main, но ветка на 12 коммитов позади, заявленный валидатор
   `verify-ledger-0038-pglite.ts` отсутствует. План: rebase → написать verifier
   по образцу verify-ops-0034-0037 → перевести вызовы на оверлоады (PAY-2).
2. **Админ-действия с выплатами не требуют 2FA.** Компенсация: роли + CAS +
   аудит-лог. TOTP-подтверждение на complete — в roadmap.
3. **Сплит колонок 2FA** (`tfa_*` legacy / `two_factor_*` живая) сохранён;
   код читает обе. Слияние одной миграцией — PAY-3.
4. **Легаси `POST /api/admin/payouts`** создаёт заявки без связи с балансом
   (деньги не двигаются — гвард reject). Переписать/удалить в cleanup.
5. **Боевой YooKassa не проверен** — только тестовый контур и mock.

## Инфраструктура

6. **VPS-деплой не прогонялся на реальном сервере** (нужны SSH/registry
   секреты владельца). Workflow переработан и валиден синтаксически; первый
   прогон — по docs/DEPLOYMENT.md с обязательным бэкапом.
7. **Host key верификация в appleboy/ssh-action** отсутствует (ограничение
   action) — для строгой безопасности self-hosted runner или ручной SSH.
8. **Docker deps через npm install** (bun.lock не читается npm-образом) —
   воспроизводимость ниже; миграция Dockerfile на oven/bun — в roadmap.
9. **Migrator не проверяет фактическую схему** против ожидаемой (только
   критические таблицы на существование).

## Продукт / UI

10. **Состав/аллергены товара** отсутствуют в схеме БД (products) — блок
    «Состав» на карточке мёртв для live-товаров; нужны колонки + UI.
11. **Категория товара** определяется угадыванием по названию (guessCategory),
    а не `category_id` из БД — фильтры каталога могут ошибаться для live-товаров.
12. **Подробные отзывы** на карточке: показывается только агрегат (рейтинг +
    счётчик), публичного списка отзывов нет.
13. **Два манифеста PWA** сведены к одному (.webmanifest), но Lighthouse-аудит
    PWA не проводился.
14. **Mock-товары витрины** (fallback при пустой БД) содержат демо-атрибуты
    (срок «1-2 дня» и т.п.) — это демонстрационный контент фикстур; live-товары
    из БД фабрикацию сроков больше не показывают. Полное отключение mock-fallback
    на production — решение владельца (сейчас пустая БД = демо-витрина).

## AI

    AbortSignal) — риск ограничен serverless-таймаутами платформы.

    — общий, не под конкретное действие.
