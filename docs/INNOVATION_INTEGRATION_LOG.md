# Журнал интеграции инноваций (Qwen / qwentopt → Conditera)

Проект-источник: github.com/uezdtort-tech/qwentopt (Vite SPA прототип, client-side only, localStorage-persistence).
Проект-приёмник: Conditera (Next.js 16 App Router + PostgreSQL, серверная бизнес-логика).
Принцип: каждое предложение оценивается по пользе, совместимости, безопасности, производительности, масштабируемости, сопровождаемости, стоимости и риску регрессий (MASTER DIRECTIVE §2, §5).

## Решения

| # | Предложение Qwen (qwentopt) | Решение | Обоснование |
|---|------------------------------|---------|-------------|
| 1 | Панель статусов внешних интеграций (src/pages-dashboard/IntegrationsPage.tsx) | **ACCEPT** | Интегрировано в ops-центр коммитом 1650bd6: объединено с реальной панелью «Система»; детекция только факта наличия env (lib/integrations-status.ts), без раскрытия значений; NOT_CONFIGURED отображается нейтрально |
| 2 | Отдельная страница корзины /cart | **ACCEPT** | Реализована коммитом 1650bd6: прямой URL открывает единственный реальный CartDrawer — без дублирования логики корзины |
| 3 | Живой чат между пользователями | **ADAPT** | В qwentopt чат — localStorage-симуляция без возможности создать диалог. В Conditera реализовано на реальном API: прямые диалоги покупатель↔кондитер (type:'direct', find-or-create), polling-доставка при недоступности socket, авто-read, обновление непрочитанных |
| 4 | 6-статусный state machine заказов (DashboardOrders) | **REJECT** | У Conditera более богатый lifecycle (src/lib/ops/lifecycle.ts, история статусов, таймлайн UI); перенос упростил бы модель без выгоды |
| 5 | KPI-семантика «выручка = только completed» | **ADAPT** | Семантика верна и принята как спецификация; реализуется на реальных данных заказов PostgreSQL (не порт кода из мок-хранилища) |
| 6 | Схема CakeProject конструктора | **REJECT** | Схема конструктора Conditera богаче: начинки из БД, региональные цены, серверный пересчёт цены на checkout |
| 7 | Events task-checklist с прогрессом и исполнителями | **DEFER** | P2-фича; в qwentopt сама функция сломана (нет UI добавления задач, работает только сид); вернуться при развитии Event Planner |
| 8 | Адаптерные утилиты (withRetry, idempotency-ключи, скраббинг секретов) | **DEFER** | Эквиваленты уже есть в Conditera (rate-limit, secure-compare, идемпотентные ключи YooKassa); дублирование бизнес-логики запрещено (§6) |
| 9 | Локальные реализации YooKassa/OAuth/SMTP (local-mode) | **REJECT — ОПАСНО** | Автоподтверждение платежей через 2с (yookassa.ts:127-134), секреты в браузере (Basic-auth из клиента :147, clientSecret :328), PKCE через btoa вместо SHA-256 (:372-376), webhook без проверки подписи (TODO :250). В Conditera реальные адаптеры: CIDR-валидация webhook, серверные ключи, честные 8 статусов |
| 10 | localStorage как БД (store.ts, ключ conditera_v3) | **REJECT — ОПАСНО** | Любые данные (включая чужие заказы и сессии) правятся из DevTools. В Conditera: PostgreSQL + серверный ACL + идемпотентность финансов |

## Протокол проверки (§6)
- Не переносить mock-логику в production: выполнено (все портированные решения работают на реальных API).
- Не считать прототип готовой функцией: qwentopt классифицирован как UI-прототип; перенесены только идеи/семантика, код — нет.
- Не считать локальный тест подтверждением работы провайдера: интеграции Conditera остаются в статусах IMPLEMENTED+LOCAL_TESTED / NOT_CONFIGURED до регистрации у провайдеров владельцем.
