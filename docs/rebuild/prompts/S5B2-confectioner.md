# ПРОМПТ S5B2 — Кабинет кондитера/поставщика

Этап 5 «Кабинеты» | Блок 2. Зависимости: S4B1 (заказы), S3B2 (products).
> Скопируйте текст ниже целиком в нового агента.

---

## 1. РОЛЬ
Ты — fullstack-разработчик. Кабинет кондитера (и поставщика декора/услуг
— общий каркас) v2: товары, заказы, календарь, аналитика, заявки выплат.

## 2. СТЕК И НЕИЗМЕНЯЕМЫЕ ПРАВИЛА
- Next.js 16 (App Router) + TypeScript strict; bun (:3000, lint, tsc).
- Tailwind CSS 4 + shadcn/ui; дизайн-система 2025; без indigo/blue.
- Данные: только Prisma; Route Handlers; CSRF/rate-limit; данные из БД.
- Процесс: коммит `[S5B2] ...`; tsc→vitest→agent-browser; worklog.md.
- Запреты: прод/секреты; mock; старый проект — только чтение.

## 3. ЦЕЛЬ БЛОКА
Кабинет продавца: управление товарами (CRUD с составом/аллергенами),
обработка заказов, аналитика, выплаты (интеграция S4B3).

## 4. ШАГИ
1. Layout (dashboard)/(confectioner): сайдбар (обзор, товары, заказы,
   календарь, аналитика, выплаты, баланс, профиль); guard по роли
   (CONFECTIONER, SUPPLIER, STUDIO, WHOLESALER — общий каркас, отличия
   в типе каталога).
2. Товары /vendor/products: таблица (пагинация, поиск), статусы
   (draft/published/hidden); форма создания/редактирования:
   - название, slug (авто), категория (select из /api/categories),
     цена/вес/сроки, опис (SafeHtml-рендер на витрине — тут просто
     textarea с предупреждением о plain-тексте),
     СОСТАВ (ingredients — теги-чипы), АЛЛЕРГЕНЫ (мультиселект из
     фиксированного списка: орехи, молоко, яйца, глютен, соя, мёд…),
     изображения (URL-список на MVP — загрузка файлов в S9B1);
   - POST /api/vendor/products (CSRF) — только свои;
   - isPublished переключатель.
3. Заказы /vendor/orders: входящие по своим товарам; статусы:
   paid → in_work → delivering (кондитер двигает); генерация
   карточки заказа (print-view для кухни); клиентские данные —
   только имя/адрес/телефон (без лишнего).
4. Календарь /vendor/calendar: заказы по датам доставки (месячная
   сетка, минимальный UI на shadcn Table).
5. Аналитика /vendor/analytics: StatCard (выручка за 30 дней,
   средний чек, конверсия paid/completed), график по дням (простая
   SVG-диаграмма или recharts), топ товаров.
6. Выплаты /vendor/payouts + баланс — уже есть (S4B3); связать
   навигацию и роли (только confectioner-группа видит).
7. Модерация: новые товары — статус draft до первого
   products.moderate (админ S5B3) — при publish: if not moderated →
   pending_moderation; админ-эндпоинт появится в S5B3, здесь —
   корректный статус и подпись в UI.

## 5. ЧТО ВЗЯТЬ ИЗ СТАРОГО ПРОЕКТА
- confectioner-dashboard компоненты — состав разделов;
- формы товаров старого проекта (поля) — адаптировать с аллергенами.

- Не публиковать товар без категории и состава (валидация).
- Не двигать статусы заказа мимо state-machine (S4B1).

## 7. КРИТЕРИИ ПРИЁМКИ
- [ ] CRUD товаров работает, состав/аллергены сохраняются и видны
      на витрине (/catalog/[slug]);
