- Данные: только Prisma; Route Handlers; ВСЕ admin-эндпоинты —
  guardAdmin + admin_actions аудит (S2B2).
- Рендер HTML из писем/заявок — ТОЛЬКО через <SafeHtml> (S2B3);
  dangerouslySetInnerHTML для внешних данных запрещён.
- Процесс: коммит `[S5B3] ...`; tsc→vitest→agent-browser; worklog.md.
- Запреты: прод/секреты; mock; старый проект — только чтение.

## 3. ЦЕЛЬ БЛОКА
Каркас админки: дашборд-обзор, модерация товаров/отзывов, пользователи
и роли (связка S2B2), очередь выплат (связка S4B3), тикеты поддержки,
входящие email (безопасный просмотр), сайт-настройки.

## 4. ШАГИ
1. Layout (dashboard)/admin: сайдбар (обзор, модерация, пользователи,
   роли, выплаты, тикеты, email, настройки); guard ADMIN/SUPER_ADMIN;
   логотип-бейдж «ADMIN».
2. Обзор /admin: StatCard (новые заказы за 24ч, на модерации,
   открытые тикеты, заявки выплат, выручка за 30 дней) + последние
   admin_actions.
3. Модерация /admin/moderation: tabs (товары pending_moderation,
   отзывы pending) — approve/reject (POST /api/admin/moderation,
   CSRF, аудит); превью товара (как на витрине).
4. Пользователи/роли: связать страницы S2B2 (поиск, назначение,
   бан/разбан — POST /api/admin/users/:id/ban c причиной, аудит).
5. Выплаты: очередь /admin/payouts — approve/reject/complete(2FA)
   (эндпоинты S4B3; здесь — UI: таблица, Dialog подтверждения с
   TOTP-полем, тосты).
6. Тикеты /admin/tickets: список (статусы open/pending/closed),
   диалог по тикету (сообщения — plain text + SafeHtml-границы),
   ответ support (POST /api/tickets/:id/reply, CSRF), смена статуса.
7. Email /admin/email: входящие письма (модель InboundEmail из
   миграции; источник — API-эндпоинт S6B2) — СПИСОК + просмотр:
   заголовки таблицей, тело письма — ТОЛЬКО через SafeHtml
   (санитизированный), вложения — список имён (скачивание в S9B1).
   XSS-тест в приёмке: письмо с <script> не исполняет.
8. Настройки /admin/settings: site_settings (ключ-значение) —
   редактирование JSON-полей (проценты бонусов, авто-complete дней,
   rate-limit AI) с валидацией схемы.
