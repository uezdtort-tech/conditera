## 2. СТЕК И НЕИЗМЕНЯЕМЫЕ ПРАВИЛА

- Тема/Zustand для клиентской корзины; серверная корзина — для auth.
- Процесс: коммит `[S4B1] ...`; tsc→vitest→agent-browser; worklog.md.
- Запреты: прод/секреты; mock-данные; старый проект — только чтение.

## 3. ЦЕЛЬ БЛОКА
Гостевая и пользовательская корзина, checkout с доставкой/датой,
создание заказа в БД со статусной моделью — без платежей (S4B2).

## 4. ШАГИ
1. Корзина:
   - Гость: Zustand persist (ключ conditera-cart): [{productId, qty}],
     синхронизация с /api/cart/guest-validate при открытии /cart
     (цены/наличие пересчитываются сервером — цены клиенту не верить);
   - Пользователь: модель Cart/CartItem в БД (миграция), merge при
     логине (гостевая + серверная);
   - UI: /cart — таблица позиций, qty-степпер, удаление, пересчёт,
     промокод-поле (ввод сохраняется, применение — S4B2);
   - Иконка корзины в шапке с бейджем количества.
2. Заказы: модели Order/OrderItem (миграция): status enum (draft,
   pending_payment, paid, in_work, delivering, completed, cancelled,
   refunded), номер заказа читаемый (CD-YYYY-NNNN), суммы:
   itemsTotal, deliveryTotal, discountTotal, total (копейки, integer).
3. Checkout /checkout (auth, CSRF):
   - Шаг 1: контакты (из профиля, редактируемые), шаг 2: доставка
     (способ: самовывоз/курьер; адрес; дата+слот; валидация даты ≥
     сегодня+1), шаг 3: подтверждение — сводка, согласия;
   - POST /api/orders (CSRF, rate-limit 5/мин) — транзакция:
     пересчёт цен из БД, создание Order+OrderItems, status
     draft→pending_payment, ответ {orderId, payment: null};
   - Метрика-цель begin_checkout (клиент).
4. Статусная модель: src/lib/orders/state-machine.ts — карта
   разрешённых переходов; служебная функция transitionOrder(orderId,
   to, actor) — использует её (с проверкой прав); транзишены логируются
   в order_events (order_id, from, to, actorId, createdAt).
5. Кабинетный зачаток: /account/orders — список заказов пользователя
   (карточки со статусом, суммой, датой) — расширит S5B1.
6. Пустые состояния и ошибки: EmptyState для пустой корзины; inline-
   ошибки валидации; тосты успеха/провала.

## 5. ЧТО ВЗЯТЬ ИЗ СТАРОГО ПРОЕКТА
- cart/checkout page-компоненты — UX-паттерн шагов и полей;
- api/orders — валидационную схему полей доставки (адаптировать);

## 6. ЗАПРЕТЫ
- Не принимать цены/скидки от клиента (только пересчёт сервером).
- Не создавать Order вне транзакции с пересчётом.
- Не забыть CSRF/rate-limit на POST /api/orders.

## 7. КРИТЕРИИ ПРИЁМКИ
- [ ] Гость кладёт в корзину, логинится — корзина мержится;
- [ ] checkout создаёт заказ со статусом pending_payment и событием
      в order_events; суммы совпадают с пересчётом;
- [ ] цены подменённые на клиенте игнорируются (тест подменой через
      curl с завышенной price → сервер пересчитал);
- [ ] /account/orders видит заказ; tsc 0; lint 0; коммит [S4B1];
      worklog.
