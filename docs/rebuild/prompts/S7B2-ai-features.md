# ПРОМПТ S7B2 — AI-функции продукта

Этап 7 «AI» | Блок 2. Зависимости: S7B1 (LLM-ядро), S3B2 (каталог).

## 1. РОЛЬ
Ты — fullstack-разработчик AI-функций. Собираешь продукт-фичи v2:
AI-ассистент, AI-поиск, сравнение, cake-finder, диалоги продавцов —
поверх LLM-ядра S7B1.

## 2. СТЕК И НЕИЗМЕНЯЕМЫЕ ПРАВИЛА
- Next.js 16 (App Router) + TypeScript strict; bun (:3000, lint, tsc).
- Tailwind CSS 4 + shadcn/ui; дизайн-система 2025; без indigo/blue.
- Backend: только Route Handlers; SDK только в backend; лимиты и
  fallback — через S7B1 (respond-обёртка); данные — только Prisma.
- Процесс: коммит `[S7B2] ...`; tsc→vitest→agent-browser; worklog.md.
- Запреты: прод/секреты; mock-ответы маскирующиеся под AI; старый
  проект — только чтение.

## 3. ЦЕЛЬ БЛОКА
Пять AI-поверхностей v2 с консистентным UX: все с loading-состояниями,
fallback-ответами, метрикой использования.

## 4. ШАГИ
1. AI-ассистент: POST /api/ai-assistant/chat (auth, CSRF, лимит
   assistant 20/мин) — контекст: корзина/последние заказы пользователя
   (в RAG-стиле передать факты в промпт); UI: виджет-кнопка (плавающая,
   правый нижний угол) + панель Dialog/Sheet: история сообщений в
   рамках сессии (модель AiConversation минимальная — 20 последних
   сообщений), typing-индикатор, fallback-ответ при недоступности LLM.
2. AI-поиск: POST /api/ai/search (лимит 30/мин) — parse запроса в
   фильтры каталога (категория/цена/аллергены-исключения) → ВЫПОЛНИТЬ
   реальный Prisma-запрос → вернуть товары + пояснение; UI: строка
   «Умный поиск» на /catalog (развёрнутый блок), результаты — те же
   ShopCard (безопасность: фильтры только whitelist-поля).
3. Сравнение: POST /api/ai/compare (лимит 10/мин) — 2–4 товара по id →
   таблица сравнения (характеристики из БД) + 3 вывода LLM; UI: на
   странице товара «Добавить к сравнению», панель сравнения
   /catalog/compare (без LLM тоже работает — таблица всегда из БД).
4. Cake-finder: POST /api/ai/cake-finder (лимит 10/мин) — анкета
   (повод, бюджет, вкусы, аллергии,Guests) → подбор 3–6 товаров из БД
   (фильтры по аллергенам — ЖЁСТКО исключить) + текст-объяснение;
   UI: /cake-finder — wizard из 4 шагов (шаги как в старом,
   адаптировать), результат — ShopCard-сетка.
5. AI-диалоги продавцов (suggestion-движок): POST /api/ai/dialogue/
   respond (роль CONFECTIONER+, лимит 20/мин) — входящий текст
   покупателя + контекст заказа → 1–2 варианта ответа; UI: кнопка
   «AI-подсказка» в чате кондитера (S6B1) — вставляет черновик в
   textarea (НЕ отправляет автоматически).
6. Метрика-цели: ai_search, ai_compare, ai_cake_finder, ai_assistant,
   ai_dialogue (client trackEvent; server для authed — опц).
7. Все ответы LLM — plain text; никакой HTML от модели не рендерится
   (протокол: модель отдаёт JSON/текст по схеме, парсинг с try/catch,
   при невалидном JSON → fallback).

## 5. ЧТО ВЗЯТЬ ИЗ СТАРОГО ПРОЕКТА
- api/ai/search, api/ai-cake-finder, api/ai-assistant/chat,
  api/ai/compare, src/lib/ai-dialogue/engine.ts — промпты и схемы
  ответов (адаптировать под respond-обёртку S7B1);
- AI-KNOWN_TASTES / AI_CATEGORY_DICT из ai-search-types.ts — словари;
- UI-паттерны виджета ассистента и wizard cake-finder.

## 6. ЗАПРЕТЫ
- Не выдавать LLM-фантазии за факты о товарах (в промпте — запрет,
  ответы только на основе переданного контекста БД).
- Не исполнять HTML от модели; не ломать rate-limits.
- Не писать тест-код; проверка — живыми вызовами.
