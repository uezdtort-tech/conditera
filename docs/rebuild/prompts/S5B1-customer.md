## 2. СТЕК И НЕИЗМЕНЯЕМЫЕ ПРАВИЛА
- Next.js 16 (App Router) + TypeScript strict; bun (:3000, lint, tsc).
- Tailwind CSS 4 + shadcn/ui; дизайн-система 2025 (StatCard, EmptyState,
  card-hover); без indigo/blue.
- Данные: только Prisma; backend — Route Handlers; CSRF на мутациях;
  все данные — из БД (никаких mock).
- Длинные списки: max-h-96 overflow-y-auto + стилизованный скролл.
- Процесс: коммит `[S5B1] ...`; tsc→vitest→agent-browser; worklog.md.
- Запреты: прод/секреты; server actions; старый проект — только чтение.

## 3. ЦЕЛЬ БЛОКА
Layout кабинета + разделы покупателя: обзор, заказы, бонусы/баланс,
избранное, профиль/адреса.

## 4. ШАГИ
1. Layout (dashboard)/(customer): сайдбар-навигация (обзор, заказы,
   избранное, баланс, профиль) — на мобайле Sheet; guard: редирект на
   / при отсутствии сессии (server component проверка).
2. Обзор /account: StatCard (заказы всего, активные, бонусы, сумма
   покупок), последние 5 заказов, быстрый переход в каталог.
3. Заказы /account/orders: список с фильтром по статусу (tabs),
   пагинация; карточка заказа: номер, дата, статус-бейдж, сумма,
   состав позиций, действия: «Оплатить» (pending_payment → S4B2),
   «Подтвердить получение» (delivering → POST /api/orders/:id/confirm,
   CSRF → completed → эскроу release), «Отменить» (draft/
   pending_payment → cancelled).
4. Избранное: модель Favorite (userId, productId) + миграция; кнопка
   «В избранное» на карточке товара (S3B2 — добавить сердечко на
   ShopCard и страницу товара); /account/favorites — сетка ShopCard.
5. Баланс/бонусы /account/balance — уже есть (S4B3); проверить
   интеграцию навигации; добавить промо-блок «как работают бонусы».
6. Профиль /account/profile: имя, телефон, город, email (readonly),
   смена пароля (POST /api/auth/password с текущим паролем), адреса
   доставки (адресная книга: модель Address, CRUD, CSRF).
7. Все экраны: Skeleton при загрузке, EmptyState при пустых списках,
   тосты на действия; server-side проверки владельца (чужой заказ →
   404, не 403 — не раскрывать существование).
