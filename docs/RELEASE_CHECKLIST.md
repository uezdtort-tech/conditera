# RELEASE CHECKLIST — чек-лист публикации Conditera

> Пройдите по пунктам строго сверху вниз. Пункт считается выполненным,
> только если его результат проверен живьём (команда/URL/скриншот), а не «по памяти».

## 1. Резервная копия и откат

- [ ] Полный бэкап БД сделан и проверен на восстановимость:
      `pg_dump -Fc -U postgres postgres > backup-$(date +%F).dump` + тестовое
      восстановление в чистый контейнер (`pg_restore --list` без ошибок).
- [ ] Известен предыдущий рабочий образ (SHA-тег в ghcr.io) для отката.
- [ ] Окно отката: сколько минут нужно на `docker compose up -d web` с
      предыдущим тегом (миграции аддитивные — старый код совместим).

## 2. Миграции

- [ ] На production-БД применены все миграции до 0039 включительно
      (ledger `schema_migrations`: `SELECT count(*) FROM schema_migrations;`).
- [ ] Если БД существовала до внедрения ledger — выполнен baseline
      (см. docs/DEPLOYMENT.md, раздел «База-лайн существующей БД»).
- [ ] dry-run migrator-контейнера на копии production-БД прошёл без ошибок.

## 3. Переменные окружения (значения НЕ коммитим и НЕ печатаем)

- [ ] Обязательные секреты заданы: `NEXT_PUBLIC_SUPABASE_URL`,
      `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`,
      `JWT_SECRET` (48+ байт), `JWT_REFRESH_SECRET`, `TFA_ENCRYPTION_KEY`
      (64 hex), `CRON_SECRET`, `POSTGRES_PASSWORD`, `NEXT_PUBLIC_APP_URL`.
- [ ] `NODE_ENV=production` — в этом режиме нет fallback-ов для секретов.
- [ ] Внешние интеграции: `YOOKASSA_SHOP_ID`/`YOOKASSA_SECRET_KEY`
      (тестовый магазин до боевого), `SMTP_*`, `TELEGRAM_BOT_TOKEN`.
- [ ] В логах при старте нет `[supabase/admin] SUPABASE_SERVICE_ROLE_KEY not set`.

## 4. Сборка и образ

- [ ] CI на коммите релиза зелёный (lint → typecheck → 744 unit-теста → build).
- [ ] Образ собран с `GIT_SHA` и тегом `sha-xxxxxxx`;
      `GET /api/health` возвращает этот SHA в поле `version`.

## 5. Тестовая оплата (тестовый контур YooKassa)

- [ ] Успешная оплата → заказ `payment_status=escrow`, запись `payments` создана.
- [ ] Повторная доставка webhook (повторный POST того же события) →
      ответ `idempotent:true`, бонусы/письма НЕ задублированы.
- [ ] Возврат (полный) → `refund.succeeded` → заказ `refunded`, сумма вернулась.
- [ ] Возврат частичный ×2 → сумма копится без дублей (RPC `apply_yookassa_refund`).

## 6. Вебхуки и уведомления

- [ ] Webhook URL зарегистрирован в YooKassa: `https://<домен>/api/payment/webhook`.
- [ ] Тестовое письмо (SMTP) доставляется; Telegram-уведомление приходит.
- [ ] Cron-эндпоинты отвечают 401 без `CRON_SECRET` и 200 с ним
      (пример: `/api/cron/escrow-release`).

## 7. Smoke-тесты (ручные, 10 минут)

- [ ] Главная → каталог → карточка товара → в корзину → checkout → заказ создан.
- [ ] Регистрация нового покупателя; логин; логин с 2FA (TOTP-код).
- [ ] Backup-код: одноразовость — второй логин тем же кодом → 401.
- [ ] Кабинет кондитера: товар создан/отредактирован; фото загружено.
- [ ] Админ: заявка на выплату видна; approve/reject с корректным 409 на повтор.
- [ ] `/robots.txt` и `/sitemap.xml` отвечают 200.

## 8. Мониторинг после релиза (первые 24–48 часов)

- [ ] `/api/health` на мониторинге (частота 1 мин, алерт на != 200).
- [ ] Логи web: нет `COMPENSATION FAILED`, `fail-closed`, `PGRST202`.
- [ ] Ошибки 5xx в access-логах < 0.5%.
