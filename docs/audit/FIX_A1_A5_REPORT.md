### 2.3. A-3 — канонический источник заработка курьера

Зафиксированная семантика (в коде обоих API):
- `orders.delivery_cost` — клиентская **цена** доставки (продуктовая величина, может меняться после назначения);
- `deliveries.cost` — снимок стоимости на момент назначения;
- `deliveries.courier_earnings` — **канонический** заработок (выплата), зафиксированный CAS-присваиванием при DELIVERED;
- legacy (delivered до sync, `courier_earnings=NULL`) → показ по `deliveries.cost` **без перезаписи финансовых данных**; backfill — отдельная согласованная миграция.

Единообразие: `/api/courier/earnings`, `/api/courier/dashboard` (KPI + история), `use-dashboards.ts` (клиент) — везде `rowEarnings = courier_earnings ?? cost ?? 0`; `orders.delivery_cost` нигде не суммируется.

Динамическая проверка с расхождением источников (заказ: `orders.delivery_cost=400`, `deliveries.cost=300`):
- завершение → `courier_earnings=300` (снимок deliveries.cost, НЕ 400 клиентской цены);
- `/api/courier/earnings`: total 1450 = 400+400+350(legacy)+300; monthly 1100 (legacy без `delivered_at` — в total входит, из monthly исключён: дата неизвестна, fabricated дата была бы подделкой);
- `/api/courier/dashboard` KPI `earningsToday=1100` = earnings.monthly — источники согласованы;
- повторное завершение (S2) — 400, удвоения нет; отмена/ошибки БД/пустые результаты — unit (route-earnings-source.test.ts в обоих API, 323 строки суммарно).
