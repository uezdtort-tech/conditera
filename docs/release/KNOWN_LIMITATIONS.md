# KNOWN LIMITATIONS — Conditera (Z-v20)

Честный реестр ограничений. Ничего из перечисленного не скрыто и не замаскировано.

## Среда выполнения (не код)

1. **4 GB песочница: kernel OOM при dev-компиляции.** `next dev` (Turbopack) достигает
   2.6–2.9 GB RSS → OOM-kill (8 событий в dmesg за сессию Z-v20). Persistent FS-cache
   осознанно отключён (его гидрация вызывала прежние 7 OOM-инцидентов — комментарий
   в `next.config.ts`). Следствие: полный chromium-профиль E2E в песочнице не завершается;
   те же спеки на mobile-chrome — 244/244. На машине ≥8 GB прогон повторится без правок.
2. **GoTrue/Supabase auth-стек локально не поднят** → `/api/health.auth = unreachable`.
   App-auth (JWT/Argon2id/2FA) работает через собственный контур; реальные
   OAuth-провайдеры не проверяемы без credentials (BLOCKED-категория).

## E2E (частичное покрытие desktop-вьюпорта)

3. Chromium UI-спеки: подтверждены частично (API-спеки 83/83; UI — до OOM-смерти
   сервера), полный desktop-прогон отложен до среды ≥8 GB. Ассерт-фейлов на момент
   остановки не зафиксировано (только connection-reset).

## Платежи и деньги

4. **Боевой YooKassa не проверен** (нет credentials) — проверен webhook-контракт,
   идемпотентность, escrow-переходы и fail-closed mock_* в production (E2E 12/12).
5. Админ-выплаты без 2FA-подтверждения (известное решение RELEASE-03); легаси
   `POST /api/admin/payouts` не двигает деньги (задокументировано ранее).
6. Anti-fraud fail-open при недоступности БД (задокументированное решение;
   login компенсирован rate-limit'ами).

## Аутентификация

7. OAuth VK — провайдер не настроен, возвращает честный 501; легаси
   `src/app/auth/callback` дублирует OAuth-контракт (архивировать после проверки ссылок).
8. Восстановление пароля — через GoTrue-контур (resetPasswordForEmail); без поднятого
   GoTrue и SMTP в песочнице не проверяем end-to-end.

## Автоматизация (n8n)

9. **Реальный n8n не развёрнут** — работает локальный приёмник (`mini-services/n8n-receiver`):
   E2E-цепочка emitter→receiver подтверждена живыми событиями (order.created ×11,
   order.status_changed и др.). 25 workflow-JSON готовы к импорту; дашборд администратора
   теперь честно показывает статус и отдаёт настоящие JSON. Активация по расписанию —
   после `docker compose up -d n8n` (владелец).
10. Дублирование механизмов автоматизации: n8n (канонический исходящий) и
    `scheduled_jobs`+pg_cron (use-automation.ts) сосуществуют. Канонизация — решение
    владельца (не блокер).

## Продукт

11. Франшиза: backend API с гардами есть, UI-потребителей нет (backend-only).
12. Аниматоры/события: страница работает на моках; `/api/events` существует, но не
    подключён к UI.
13. Decor-shop: витрина реальная; checkout декора как отдельного заказа отсутствует.
14. Каталог dual-mode: при пустой БД остаётся demo-seed с Unsplash-фото (решение
    владельца; real-фото продукции — контент от владельца).
15. Категории каталога — статический словарь UI (lib/mock-data), SQL-фасеты аллергенов
    — клиентский движок (продуктовый поиск), не PostgREST.
16. Две карты переходов статусов заказа (ops/lifecycle.ts и легаси-карта в
    orders/[id]/route.ts PATCH) — синхронизированы по покрытию тестами, унификация
    отложена (рефакторинг-риск перед релизом).
17. Микротекст <12px остаётся в части UI (792 вхождения; критичные карточки поправлены).
18. CSP с 'unsafe-inline'/'unsafe-eval' (nonce-рефакторинг — после релиза).
19. In-memory rate-limit/троттлинг без Redis — single-instance only.

## Инфраструктура

20. Внешний backup storage не настроен (RPO ограничен жизнью машины) — см.
    OWNER_ACTIONS_REQUIRED §C.10.
21. GitHub Actions никогда не запускались (push запрещён) — вердикт READY FOR STAGING,
    а не READY FOR RELEASE, в том числе поэтому.
