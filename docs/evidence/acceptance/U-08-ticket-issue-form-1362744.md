### FINDING (needs owner decision): ticket list rows have no `id` field

`GET /api/crm/tickets` (both `filter=all` and `filter=own`) returns rows **without the `id` column** — clients cannot reference a ticket by id from the list (e.g. for `PATCH /api/crm/tickets/[id]`), only by `number`/`subject`.
Root cause (static, no code changed): the local PostgREST shim drops the parent's linking PK when a 1-level embed is requested even though `*` was explicitly selected — `src/lib/postgrest/translate.ts:433-441` adds the join column (`id`) to `hidden`, and `:519-523` deletes it from output; the check at `:438` does not treat `*` as covering the join column. Real PostgREST would return `id` for `select=*,rel(...)`. Fix is one condition in the shim; left to owner (core infra, out of acceptance scope).
