# PRODUCT_BACKLOG — единый реестр задач продукта (Z-v31)

**Назначение.** Это ЕДИННЫЙ реестр задач и находок. Новые аудит-файлы на каждую правку НЕ создаются — находка добавляется строкой сюда. Процесс работы с записями (обнаружение → классификация → задача → исправление → верификация) — `docs/operations/PRODUCT_OPERATING_SYSTEM.md` §6.

**Правила ведения:**

- **Статусы:** `OPEN` (взята в реестр) → `IN_PROGRESS` (есть ответственный/начата) → `DONE` (критерий завершения выполнен и проверен) или `NOT_PLANNED` (снята — только с указанием причины и решившего владельца в конце строки/в комментарии). `REOPENED` фиксируется возвратом в `OPEN` с пометкой.
- **Приоритеты:** `P0` (деньги/безопасность/доступность — блокирует релиз) · `P1` (критичный функционал) · `P2` (важное, не блокирует) · `P3` (улучшение) · `P4` (косметика/инструменты).
- **Критерий завершения обязателен** для каждой строки: без проверяемого критерия строка не считается задачей. `DONE` ставится только по факту выполнения критерия, а не по намерению.
- **Доказательство** — фактический файл/строка/наблюдение сессии (Z-v31), а не предположение. Если доказательство устарело — обновить или закрыть как NOT_PLANNED.
