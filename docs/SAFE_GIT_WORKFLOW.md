# SAFE GIT WORKFLOW — работа с репозиторием в среде с автокоммитером

> Инструкция составлена по итогам инцидентов №1–№5 (см. worklog.md). Если вы
> работаете с этим репозиторием из песочницы/автоматизированной среды, где
> внешний процесс может коммитить и переключать ветки за вашей спиной —
> следуйте этому протоколу. В обычной среде (обычный CI, локальная машина)
> инструкция избыточна.

## Природа проблемы

В песочнице платформы присутствует watcher-процесс, который:
1. **Автокоммитит** изменения в рабочем дереве с UUID-сообщениями
   (`f1bfbce1-4dc0-...`, `6885f0e5-1bb2-...`) — инциденты №1–№3;
2. **Переключает HEAD/сбрасывает рабочее дерево** к «своей» версии main
   между командами агента — инциденты №4–№5 (worklog-коммит лёг на мусорную
   базу `e3ed55c`, push ушёл без него).

## Протокол (обязательный порядок)

### До работы
1. Не доверять текущему checkout. Истинное состояние узнавать через **объекты**,
   а не рабочее дерево: `git show <ref>:<path>`, `git grep <pat> <ref>`,
   `git log <ref>` — они не зависят от того, куда watcher переключил HEAD.
2. Изолированные задачи — в **worktree**: `git worktree add /tmp/wt <ref>`.
   Watcher переключает HEAD основного клона, worktree не трогает.

### Перед каждым коммитом
3. `git branch --show-current` — ветка та, что вы думаете?
4. `git status --short` — в стейдже ТОЛЬКО ваши файлы? Посторонние UUID-файлы
   (`download/`, bundle-артефакты) — признак автокоммитера.
5. `git diff --cached --stat` — объём соответствует замыслу?
6. Аппенды worklog логов коммитить НЕМЕДЛЕННО той же командой, что и правку
   (закрывает окно для автокоммитера):
   `cat >> worklog.md <<'EOF' ... EOF && git add worklog.md && git commit -m "docs(worklog): ..."`

### После каждого коммита
7. `git log --format='%h parent:%p %s' -1` — SHA, родитель и сообщение ожидаемые?
8. `git show --stat HEAD` — только ваши файлы?

### Перед push
9. `git fetch origin && git ls-remote origin refs/heads/<branch>` — удалённый
   ref совпадает с локальным родителем вашего коммита (нет чужих коммитов)?
10. Push только forward; force — только `--force-with-lease` с осознанной целью.
11. После push: `git ls-remote origin refs/heads/<branch>` == локальный HEAD.

### Креды
12. Токен — одноразовым credential-helper (`git -c credential.helper='!f() { ... }; f' push ...`),
    НИКОГДА в `remote.url`, `~/.git-credentials`, env-файлах, истории команд.

## Чек-лист расследования инцидента (если HEAD «поехал»)

```bash
git reflog -20                          # кто и куда переключал
git reflog show origin/main -10         # двигался ли remote-tracking ref
git log --oneline <good-ref>..<HEAD>    # что попало в подозрительные коммиты
git show --stat <suspicious-sha>        # их содержимое (junk или данные?)
git branch backup-rescue <suspicious-sha>   # спасти до разбора
```
Отделяйте факты (reflog, SHA, содержимое) от интерпретаций. Источник истины
об изменениях на GitHub — `git ls-remote`, а не локальные ветки.
