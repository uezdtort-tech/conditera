## Сделано
- **Миграция 0057_order_reviews.sql** (СТРОГО 0057, 0056 не занят на момент работы): product_reviews + order_id UUID NULL REF orders ON DELETE SET NULL, photos JSONB DEFAULT '[]', idx_reviews_order; idempotent. Применена `bun scripts/db/setup.mjs --seed-only` → ledger 56 files (0057 виден). Проверено pg-запросом: колонки + индекс на месте.
- **POST /api/reviews** (+ в существующем route.ts, GET не тронут): auth (getUserFromRequest); валидация orderId-UUID/rating 1-5/фото ≤3/text ≤2000; заказ → владелец (403) → статус DELIVERED|COMPLETED (422) → order_items[0].product_id (NULL → 422 «Товар недоступен для отзыва») → 409 по order_id («Отзыв по этому заказу уже отправлен») → 409 по UNIQUE(product_id,user_id) («Вы уже оставляли отзыв на этот товар», + ловля гонки 23505). status='approved' — осознанно: конвейера auto-approve в системе нет, seed пишет approved, публичный GET читает только approved; ручная модерация в админке сохранена.
- **GET /api/reviews?mine=1** — свои отзывы (любой статус) с order_id/productId/photos: источник состояния «Отзыв отправлен» (переживает перезагрузку). Публичный GET ?limit= работает как раньше.
- **POST /api/orders/[id]/repeat — новый контракт** (заказ НЕ создаётся): {orderNumber, currency:'RUB', items:[{productId,title,image,quantity,unitPrice(актуальная),oldPrice(snapshot),available,unavailableReason?}]}. Проверки: product существует / status='published' / is_available (0052). 422 если нет повторяемых позиций (custom без product фильтруются). Auth заменён getCurrentUser (Supabase-cookie, app-JWT не видел → «Не авторизован») на getUserFromRequest + isAdmin(role-guards) — как в /api/orders и /cancel.
- **/api/wishlist (НОВЫЙ)**: GET — карточки {productId,id,title,price,images,slug,available} из product_favorites JOIN products, фолбэк-обложка из product_images; POST {productId} toggle; DELETE ?productId=. UUID-валидация, 404 на несуществующий товар, скоуп только свои (user_id), auth обязателен.
- **POST /api/crm/tickets** — passthrough metadata (фильтр: скаляры + string[]), иначе тикет без описания/фото (ТЗ §16). GET ?filter=own уже фильтрует по user — UI использует его; роль-доступ не менялся (клиент и раньше мог POST).
- **chat-order-bridge.ts (НОВЫЙ)**: openChatForOrder() dispatch + useChatOrderBridge() в dashboard/page.tsx → <ChatWidget initialOrderId={...}> (оба маунта). chat-widget.tsx НЕ трогал (зона p1-b), prop уже зарезервирован.
- **customer-dashboard.tsx** (расширен, существующие секции не переписаны): кнопка «Оставить отзыв» (замена заглушки) → диалог «Как вам заказ?» (интерактивные звёзды, текст, ≤3 фото через /api/upload category=reviews, лимит 5МБ/файл клиентски) → POST → кнопка «Отзыв отправлен» (disabled, из reviews-mine); кнопка «Есть проблема» (везде кроме CANCELLED/REFUNDED) → radio 4 причины → category product_quality/order_issue/delivery/other, описание ≥10, ≤3 фото (category=tickets) → POST тикет; бейдж открытого тикета на карточке заказа (TICKET_BADGES: open/in_progress/waiting); «Повторить заказ» (DELIVERED/COMPLETED) → POST repeat → все available и без смены цен → сразу addToCart (+toast, корзина открывается сама), иначе диалог: цена изменилась old→new, недоступные с причиной (НЕ добавляются), кнопка «Добавить в корзину (N)»; кастомизация позиции (filling/coating/decoration/inscription) переносится в addToCart; «Отменить заказ» (PENDING/CONFIRMED) → AlertDialog → POST /api/orders/[id]/cancel → invalidate orders-real; «Чат с кондитером» → «Сообщение кондитеру»: ensureChatRoom({type:'order',orderId}) → openChatForOrder → setChatOpen(true), null → тост «Чат временно недоступен»; таб «Избранное»: при залогине — WishlistGrid из /api/wishlist (карточка: фото, цена, [В корзину] min-Product через addToCart, сердечка → POST toggle), фолбэк localStorage при ошибке/анониме; бейдж сайдбара = серверный счётчик.
