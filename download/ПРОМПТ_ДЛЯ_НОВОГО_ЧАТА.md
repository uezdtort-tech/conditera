# ПРОМПТ ДЛЯ НОВОГО ЧАТА
## Маркетплейс кондитерских услуг «Уездный кондитер» v2.0 — полная реконструкция на self-hosted Supabase

---

## 🎯 КОНТЕКСТ ПРОЕКТА

Создаёшь маркетплейс кондитерских изделий и услуг «Уездный кондитер» — российский аналог Goldbelly/CakeIt, объединяющий покупателей, домашних кондитеров, поставщиков ингредиентов, курьеров и администраторов. Проект уже существует в v1.0 (Next.js 16 + Prisma 7 + PostgreSQL), но из-за каскадных ошибок (PGlite WASM OOM, Prisma Proxy-обёртка, 12 конфликтующих Docker-сервисов, конфликты PostgreSQL volume versions, Cloudflare Tunnel 502) принято решение о полной реконструкции на self-hosted Supabase.

### Бренд и домен
- **Название:** «Уездный кондитер» (не «Кондитера», не «Уездный»)
- **Домен:** `conditera.ru` (+ www.conditera.ru)
- **Telegram-канал:** @conditera
- **Фирменные шрифты:** Brokgauz & Efron Italic (заголовки), TriodPostnaja Medium (брендовое название), Neucha (рукописный), Geist/Geist Mono (body)
- **Палитра:** тёмно-ягодный #8B2942 (primary), амбер #D97706 (accent), slate #1F2937 (body)
- **Стиль:** дореволюционный кондитерский колорит, энциклопедическая антиква + современный UX

### Цель v2.0
Полностью рабочий маркетплейс с сохранением **всего** функционала v1.0 (без урезаний), но на новой архитектурной базе. Запуск одной командой `docker compose up -d` без ручных правок. Срок: 14 дней.

## 🏗️ АРХИТЕКТУРА

### Стек v2.0 (замены из v1.0)

| Компонент v1.0 | Компонент v2.0 | Причина замены |
|---|---|---|
| PGlite (WASM Postgres) | **Supabase Postgres 15** | OOM при сборке, несовместимость с Turbopack |
| Prisma v7 + Proxy-обёртка | **supabase-js + PostgREST** | Теряет типы, ломает tree-shaking |
| Socket.IO + Redis | **Supabase Realtime** (postgres_changes) | Избыточно, отдельный контейнер + Redis |
| n8n | **pg_cron + Supabase Edge Functions** (Deno) | Сложность debug workflows |
| Meilisearch | **Postgres FTS** (tsvector + GIN + pg_trgm) | 512MB RAM, отдельный контейнер |
| Telegram-бот (Node.js) | **Supabase Edge Function** | Дублирует auth логику |
| Самописный JWT auth | **Supabase GoTrue** (email/pass, OAuth, Magic Link, TOTP) | Сложность поддержки 2FA/OAuth |
| S3-like storage (custom) | **Supabase Storage** + imgproxy | Нет thumbnail generation |
| Prisma safeSelect | **Postgres RLS policies** | Безопасность на уровне БД |
| Cloudflare Tunnel → web:3000 | **Cloudflare Tunnel → Caddy:80** | Health-check обрабатывает 502 |

### Docker-стек (единый docker-compose.yml, 13 контейнеров)

1. **supabase-db** — PostgreSQL 15.6 с расширениями (pgsodium, pg_cron, pg_trgm)
2. **supabase-analytics** — Logflare для логирования
3. **supabase-auth** — GoTrue (auth сервис)
4. **supabase-rest** — PostgREST (auto REST API)
5. **supabase-realtime** — WebSocket подписки на postgres_changes
6. **supabase-storage** — S3-совместимое хранилище
7. **supabase-imgproxy** — обработка изображений (resize, crop)
8. **supabase-kong** — API gateway (единая точка входа :8000)
9. **supabase-meta** — postgres-meta (управление схемой)
10. **supabase-studio** — Web UI (БД, Auth, Storage, Functions)
11. **web** — Next.js 16 приложение
12. **caddy** — reverse proxy + авто-HTTPS
13. **telegram-bot** — Edge Function (Deno runtime)

### Поток запроса
Пользователь → Cloudflare (DNS+WAF+DDoS) → Cloudflare Tunnel → Caddy:80 → web:3000 (Next.js SSR) → supabase-kong:8000 → {gotrue, postgrest, realtime, storage} → supabase-db:5432

### Деплой
GitHub Actions → SSH → `docker compose up -d`. Cloudflare Tunnel (cloudflared) → http://localhost:80 (Caddy, **НЕ** напрямую к web:3000).

## 💰 ФИНАНСОВЫЕ СТРУКТУРЫ И МОДЕЛИ

### Сущности финансинга

#### 1. Заказы и платежи
```
Order (заказ)
├── status: OrderStatus (PENDING → NEGOTIATING → CONFIRMED → PREPARING → READY → IN_DELIVERY → DELIVERED → COMPLETED | CANCELLED | REFUNDED)
├── totalAmount (итоговая сумма)
├── confectionerId (исполнитель)
├── customerId (заказчик)
├── items[]: OrderItem
│   ├── productId (snapshot)
│   ├── quantity
│   ├── priceSnapshot (цена на момент заказа)
│   └── customOptions (для конструктора)
├── payment: Payment (1:1)
│   ├── yookassaPaymentId
│   ├── status: PaymentStatus (pending | waiting_for_capture | succeeded | escrow | released | cancelled | refunded)
│   ├── method: PaymentMethod (card | sbp | cash | split | installment | yookassa | self)
│   └── escrowReleasedAt (для эскроу-выплат)
└── delivery: Delivery (1:1)
    ├── address, lat, lng
    ├── courierId
    ├── deliveryType: courier | pickup | self_pickup
    └── deliveryCost
```

#### 2. Финансы кондитера
```
Confectioner
├── accountType: AccountType (individual | legal)
├── taxMode: TaxMode (NPD | USN | OSNO | PSN | SELF_EMPLOYED)
├── tariff: Tariff (START | BASIC | PREMIUM | BUSINESS) — абонентская плата
├── trustLevel: TrustLevel (NEW | VERIFIED | MASTER | EXPERT)
├── balance: текущий баланс (pending + available)
├── totalEarnings: общая сумма заработка
├── commissionRate: % комиссии платформы (зависит от тарифа)
└── payouts[]: PayoutRequest
    ├── amount (сумма к выплате)
    ├── status: pending | approved | rejected | paid
    ├── bankDetails
    └── payoutMethod: card | sbp | invoice
```

#### 3. Комиссии и тарифы
- **START** — 0₽/мес, комиссия 15% с заказа
- **BASIC** — 990₽/мес, комиссия 10%
- **PREMIUM** — 2990₽/мес, комиссия 7%
- **BUSINESS** — 9900₽/мес, комиссия 5%, приоритет в выдаче

#### 4. Бонусы и лояльность
```
LoyaltyTransaction
├── type: LoyaltyTxType
│   ├── EARN — начисление за заказ (1 бонус = 1 рубль)
│   ├── REDEEM — списание при оплате (1 бонус = 1 рубль скидки)
│   ├── EXPIRE — сгорание через 12 месяцев
│   ├── REFUND — возврат при отмене заказа
│   ├── ADJUST — ручная корректировка админом
│   ├── BONUS_WELCOME — приветственные +500 при регистрации
│   ├── BONUS_BIRTHDAY — +1000 в день рождения
│   └── BONUS_REFERRAL — +300 за приглашённого друга
├── amount: количество бонусов
├── orderId?: связанный заказ
└── expiresAt: дата сгорания

LoyaltyLevel: BRONZE (0+) | SILVER (10k+) | GOLD (50k+) | PLATINUM (200k+)
— влияет на % кэшбэка: 3% / 5% / 7% / 10%
```

#### 5. Реферальная программа
```
Referral
├── referrerId (кто пригласил)
├── refereeId (кого пригласили)
├── bonusForReferrer: 300₽ (после первого заказа реферала)
├── bonusForReferee: 500₽ (на первый заказ)
├── status: pending | completed | expired
└── completedAt: когда реферал сделал первый заказ
```

#### 6. Подарочные сертификаты
```
GiftCertificate
├── code: уникальный код (например "CONDIT-XXXX-XXXX")
├── amount: номинал (500, 1000, 3000, 5000, 10000)
├── purchaserId (кто купил)
├── recipientEmail (кому отправлен)
├── status: purchased | activated | used | expired
├── expiresAt: 12 месяцев
├── paymentId: связанный платёж Yookassa
└── appliedToOrderId: заказ, к которому применён
```

#### 7. Промокоды и акции
```
PromoCode
├── code: "WELCOME10", "BIRTHDAY2026"
├── type: percent | fixed | free_delivery
├── value: 10 (% ) | 500 (₽) | null
├── minOrderAmount: минимальная сумма заказа
├── maxUses: лимит использований
├── usedCount: текущее количество
├── validFrom, validTo: период действия
├── appliesTo: all | first_order | specific_category | specific_confectioner
└── usages[]: PromoCodeUsage (кто, когда, к какому заказу)

PromoCampaign — связывает несколько промокодов для маркетинговой кампании
```

#### 8. Оптовые цены и подписки
```
WholesalePrice
├── productId
├── minQuantity: минимум для оптовой цены
├── pricePerUnit: цена за единицу
└── appliesTo: WHOLESALER | FOOD_SERVICE | CORPORATE_CLIENT

CakeSubscription — подписка на регулярную доставку тортов
├── customerId
├── frequency: weekly | biweekly | monthly
├── productTemplate: параметры торта
├── nextDeliveryAt
├── status: active | paused | cancelled
└── paymentMethodId

RecurringOrder — автоматически создаваемый заказ по подписке
```

#### 9. Возвраты и споры
```
Refund
├── orderId
├── amount: сумма возврата
├── reason: customer_request | quality_issue | damaged | not_delivered | other
├── status: requested | approved | processed | rejected
├── initiatedBy: customer | admin | confectioner
├── yookassaRefundId
└── processedAt

OrderFraudLog — лог антифрод-проверок
├── orderId
├── riskScore: 0-100
├── flags: rapid_orders | mismatched_geo | stolen_card | vpn | emulator
└── action: allow | review | block
```

#### 10. Налоги и отчётность
```
TaxReport
├── period: monthly | quarterly | yearly
├── confectionerId
├── grossIncome: валовый доход
├── platformCommission: комиссия платформы
├── netIncome: чистый доход
├── taxMode: NPD | USN | OSNO | PSN | SELF_EMPLOYED
├── calculatedTax: расчётный налог
├── generatedAt, sentAt
└── pdfUrl: ссылка на PDF-отчёт (через Supabase Storage)

InsuranceContribution — добровольное страхование заказов
├── orderId
├── amount: 1% от стоимости заказа
├── coverage: damaged | not_delivered | quality_issue
└── status: paid | claimed | expired

BusinessExpense — расходы кондитера (ингредиенты, упаковка, доставка)
├── confectionerId
├── category: ingredients | packaging | delivery | equipment | marketing | other
├── amount, date, description
└── receiptUrl: фото чека (через Supabase Storage)

FinancialAuditLog — аудит всех финансовых операций
├── userId: кто совершил
├── action: payout_request | refund_processed | tax_report_generated | etc.
├── entityType, entityId: что изменено
├── oldValue, newValue (JSONB)
└── ipAddress, userAgent
```

### Финансовые flows

#### Эскроу-выплата (по умолчанию для всех заказов)
1. Покупатель оплачивает → Yookassa → деньги на escrow-счёт платформы
2. Заказ доставлен → статус `DELIVERED`
3. Через 7 дней (или по запросу кондитера) → деньги списываются с escrow
4. Платформа удерживает комиссию (5-15% по тарифу)
5. Остаток → на баланс кондитера
6. Кондитер выводит через PayoutRequest (минимум 5000₽)

#### Возврат
1. Покупатель запрашивает возврат через /api/refunds (если статус заказа < COMPLETED)
2. Авто-проверка: если <24ч и сумма <5000₽ → авто-возврат
3. Иначе → ручная проверка админом
4. Yookassa refund API → деньги возвращаются покупателю
5. Заказ → status=CANCELLED или REFUNDED
6. Бонусы (если начислялись) → списываются через LoyaltyTxType.REFUND

## 🔐 БЕЗОПАСНОСТЬ (RLS политики)

### Принцип
Каждая таблица с user data имеет RLS-политики. PostgREST автоматически фильтрует по `auth.uid()`.

### Примеры политик

```sql
-- Пользователь видит только свои заказы
CREATE POLICY "users_select_own_orders" ON orders
  FOR SELECT USING (auth.uid() = user_id);

-- Кондитер видит заказы где он назначен
CREATE POLICY "confectioner_select_assigned_orders" ON orders
  FOR SELECT USING (
    EXISTS (SELECT 1 FROM order_items oi
            JOIN products p ON oi.product_id = p.id
            WHERE oi.order_id = orders.id AND p.confectioner_id = auth.uid())
  );

-- Участники канала видят сообщения
CREATE POLICY "members_select_messages" ON chat_messages
  FOR SELECT USING (
    EXISTS (SELECT 1 FROM chat_channel_members
            WHERE channel_id = chat_messages.channel_id
            AND user_id = auth.uid())
  );

-- Только админ может создавать промокоды
CREATE POLICY "admin_insert_promocodes" ON promo_codes
  FOR INSERT WITH CHECK (
    EXISTS (SELECT 1 FROM user_roles
            WHERE user_id = auth.uid() AND role IN ('ADMIN', 'SUPER_ADMIN') AND is_active = true)
  );
```

### Security headers (через Caddy + Next.js)
- CSP: `default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval' https://yookassa.ru https://*.yoomoney.ru; ...`
- HSTS: `max-age=31536000; includeSubDomains; preload`
- X-Frame-Options: SAMEORIGIN
- Permissions-Policy: geolocation=(), microphone=(), camera=(), payment=()
- COOP/CORP: same-origin

### CSRF
В Supabase Auth session-based, CSRF токен генерируется на сервере, проверяется timing-safe. Каждый POST требует `X-CSRF-Token` header.

### Rate limiting
- `/api/auth/*` — 5 запросов/мин на IP
- `/api/payment/*` — 10 запросов/мин на пользователя
- `/api/search` — 60 запросов/мин на IP
- Общие `/api/*` — 100 запросов/мин на IP

## 🚨 ВАЖНЫЕ ПРАВИЛА ДЛЯ РАЗРАБОТЧИКА

1. **Брендовое название** всегда «Уездный кондитер» — не «Кондитера», не «Уездный». Это особенно важно в Header, Footer, email-шаблонах, SEO title.

2. **Домен** всегда `conditera.ru` — не `uyezdny.ru`. Это касается Caddyfile, Cloudflare Tunnel config, CSP headers, метатегов.

3. **Запрещены** PGlite, Prisma, Socket.IO, Redis (для adapter), n8n, Meilisearch, SimpleX — все эти технологии заменены на Supabase аналоги.

4. **Все таблицы с user data** должны иметь RLS-политики. Никаких проверок в коде вида `if (user.id !== order.userId) return 403` — это должно быть на уровне БД.

5. **Все API endpoints** должны быть типизированы через TypeScript типы, генерируемые из Supabase schema: `supabase gen types typescript --local > src/types/supabase.ts`.

6. **Все формы** валидируются через Zod-схемы (есть в `src/lib/validation/`).

7. **Все financial операции** логируются в `FinancialAuditLog` (oldValue, newValue, userId, ipAddress).

8. **Backup** БД каждый день в 3:00 MSK через `scripts/backup.sh` + cron. Хранение 30 дней.

9. **Деплой** только через GitHub Actions. Никаких ручных `docker compose up` на production (только для отладки).

10. **Скриншоты** после каждого этапа — обязательны, сохраняются в `/home/z/my-project/download/screenshots/`.

11. **Сначала ТЗ** (см. `/home/z/my-project/download/ТЗ_Уездный_кондитер_v2.0_Supabase.docx`), потом код. Если что-то не описано в ТЗ — спросить, не предполагать.

12. **Проверка на каждом шаге**: после каждого модуля — unit-тесты + e2e + health-check + скриншоты. Не накапливать технический долг.
