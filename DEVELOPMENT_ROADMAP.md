## P1 — критичные укрепления (независимо от Production)

### P1-1. Argon2id-миграция хэшей паролей
- **Доказательство**: `src/lib/auth.ts:128-140` bcryptjs; комментарии «Argon2id» ложные (`api/auth/login/route.ts:9`).
- **Решение**: `hashPassword` → Argon2id (@node-rs/argon2); `verifyPassword` — dual по префиксу (`$2b$`→bcrypt, `$argon2id$`→argon2); пере-хэш при успешном входе. Совместимо с GoTrue-only юзерами (у них нет `profiles.password_hash`).
- **Риски**: несовместимость старых хэшей — решается dual-verify; зависимости нативного модуля — проверить сборку Docker.
- **Тесты**: существующий auth-suite + новые векторы (roundtrip, legacy-hash verify, re-hash on login).
- **Готово**: новые пользователи — Argon2id; старые логинятся без сброса; комментарии соответствуют коду.
- **Зависимости**: нет (локальная БД есть).

### P1-2. Fail-closed blocked-check для мутирующих запросов — **ВЫПОЛНЕНО 2026-11-16**
- **Реализация**: `src/lib/auth.ts` `getUserFromRequest` — POST/PUT/PATCH/DELETE при ошибке blocked-check → null (роут вернёт 401); GET/HEAD — fail-open; кэш не заполняется при ошибке. Тесты: `auth-blocked-check.test.ts` (12). E2E: session 403 + cookies очищены, мутация после TTL → 401. Детали: `AUTH_ROOT_CAUSE_REPORT.md` §6B.

### P1-3. Timing-safe сравнение X-Cron-Secret / X-N8N-Secret — **ВЫПОЛНЕНО 2026-11-16**
- **Реализация**: `src/lib/cron-auth.ts` → `timingSafeEqualStr` (n8n/telegram/simplex/CSRF уже были timing-safe). Тесты: `cron-auth.test.ts` (10). Детали: `AUTH_ROOT_CAUSE_REPORT.md` §6C.

### P1-4. zod-валидация auth-роутов — частично (email-валидация добавлена 2026-11-16)
- **Реализовано**: email-формат/trim-нормализация в register до БД/GoTrue (400 «Некорректный формат email»); 409 для GoTrue-дубликатов. Полное подключение `loginSchema`/`registerSchema` — остаётся (сохранить текущие коды ошибок — обратная совместимость API).
- **Тесты**: register/route.test.ts расширен (409-по-code, email-валидация, нормализация).

### P1-5. Восстановление Production (координация с Pi, не код)
- Регистрация на проде: деплой `cb42589+` после восстановления PostgREST/Caddy; проверить цепочку register→login→RLS. См. `PRODUCTION_COMPATIBILITY.md` §2.
- **Зависимости**: Pi/владелец.
