    62→### Модуль 1: Auth (аутентификация)
    63→**Возможности:**
    64→- Email + password регистрация и логин
    65→- Email confirmation (письмо с подтверждением)
    66→- Password reset (forgot password flow)
    67→- Magic Link (бесшарольный вход)
    68→- OAuth: Google, Яндекс, ВКонтакте
    69→- 2FA через TOTP (Google Authenticator, Authy)
    70→- Session management: access token (1 час) + refresh token (7 дней)
    71→- Row Level Security (RLS) на уровне БД
    72→
    73→**Таблицы БД:**
    74→- `auth.users` — встроенная GoTrue
    75→- `auth.identities` — OAuth providers
    76→- `auth.sessions` — активные сессии
    77→- `auth.mfa_factors` — 2FA TOTP secrets
    78→- `public.profiles` — расширение auth.users (full_name, avatar_url, phone, city, address)
    79→- `public.user_roles` — множественные роли (user_id, role, is_active)
    80→
    81→**API Endpoints:**
    82→```
    83→GET    /api/auth/callback       - OAuth redirect callback
    84→POST   /api/auth/refresh        - Обновить access token
    85→POST   /api/auth/logout         - Выход (revoke session)
    86→GET    /api/auth/check          - Проверка сессии
    87→GET    /api/profile             - Получить профиль
    88→PATCH  /api/profile             - Обновить профиль
    89→POST   /api/profile/avatar      - Загрузить аватар
    90→PATCH  /api/profile/password    - Сменить пароль
    91→DELETE /api/profile/delete      - Удалить аккаунт
    92→```
    93→
    94→**UI Компоненты:**
    95→- `AuthModal` — модалка входа/регистрации (email+pass, OAuth, Magic Link)

   274→- canProceed: `!!city && !!deliveryDate && !!deliveryType`

   276→**Шаг 7: Резюме + Кондитеры (обязательно)**
   277→- Заголовок: "Выберите кондитеров"

   279→- canProceed: `selectedConfectioners.length > 0`

   281→**Формула расчёта цены:**
   282→```
   283→estimatedPrice = 1500                               // базовая цена (8 порций)
   284→               + base.priceBase                     // + основа (0-400 ₽)
   285→               + filling.price                      // + начинка (0-400 ₽)
   286→               + coating.price                      // + покрытие (0-500 ₽)
   287→               + SUM(decorations[].price)           // + декор (мультивыбор)
   288→               + MAX(0, servings - 8) × 180         // + доп. порции
   289→
   290→deliveryCost   = calculateDelivery(estimatedPrice)  // 0 при ≥3000₽, иначе 300+50/км
   291→                 if deliveryType === "delivery", else 0
   292→
   293→total          = estimatedPrice + deliveryCost
   294→               × (1 - discountPercent / 100)        // если запрошена скидка
   295→```

   606→### Модуль 10: Payments (платежи Yookassa)
   607→**Возможности:**
   608→- Создание платежа через Yookassa
   609→- Webhook для подтверждения платежа
   610→- Эскроу-счёт (деньги замораживаются до подтверждения)
   611→- Возвраты (рефанды)
   612→- Комиссии платформы (5-15% по тарифу)
   613→- Выплаты кондитерам
   614→
   615→**Поток платежа:**
   616→1. Пользователь оформляет заказ → POST /api/checkout
   617→2. Backend создаёт payment в Yookassa
   618→3. Yookassa возвращает confirmation_url → редирект пользователя
   619→4. Пользователь вводит карту, оплачивает на стороне Yookassa
   620→5. Yookassa отправляет webhook на /api/payment/webhook (payment.succeeded)
   621→6. Backend обновляет order.status = paid, отправляет уведомления
   622→
   623→**Таблицы БД:**
   624→```sql
   625→payments (id, order_id, yookassa_payment_id, status, amount, method, escrow_released_at, refund_id, created_at)
   626→refunds (id, order_id, amount, reason, status, yookassa_refund_id, processed_at)
   627→payout_requests (id, confectioner_id, amount, status, bank_details, paid_at, created_at)
   628→```
   629→
   630→**API Endpoints:**
   631→```
   632→POST   /api/payment/create    - Создать платёж
   633→POST   /api/payment/webhook   - Webhook от Yookassa
   634→POST   /api/payment/refund    - Создать возврат
   635→GET    /api/payment/status    - Статус платежа

   843→## 🔐 БЕЗОПАСНОСТЬ (RLS политики)
   844→
   845→**Принцип:** Каждая таблица с user data имеет RLS-политики. PostgREST автоматически фильтрует по `auth.uid()`.
   846→
   847→**Примеры политик:**
   848→```sql
   849→-- Пользователь видит только свои заказы
   850→CREATE POLICY "users_select_own_orders" ON orders
   851→  FOR SELECT USING (auth.uid() = user_id);
   852→
   853→-- Кондитер видит заказы где он назначен
   854→CREATE POLICY "confectioner_select_assigned_orders" ON orders
   855→  FOR SELECT USING (
   856→    EXISTS (SELECT 1 FROM order_items oi
   857→            JOIN products p ON oi.product_id = p.id
   858→            WHERE oi.order_id = orders.id AND p.confectioner_id = auth.uid())
   859→  );
   860→
   861→-- Участники канала видят сообщения
   862→CREATE POLICY "members_select_messages" ON chat_messages
   863→  FOR SELECT USING (
   864→    EXISTS (SELECT 1 FROM chat_channel_members
   865→            WHERE channel_id = chat_messages.channel_id
   866→            AND user_id = auth.uid())
   867→  );
   868→
   869→-- Только админ может создавать промокоды
   870→CREATE POLICY "admin_insert_promocodes" ON promo_codes
   871→  FOR INSERT WITH CHECK (
   872→    EXISTS (SELECT 1 FROM user_roles
   873→            WHERE user_id = auth.uid() AND role IN ('ADMIN', 'SUPER_ADMIN') AND is_active = true)
   874→  );
   875→```

   879→- HSTS: `max-age=31536000; includeSubDomains; preload`
